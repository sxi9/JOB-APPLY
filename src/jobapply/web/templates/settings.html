Auto-submit stays off until a few dry runs on that site look right in the Queue. The global dry-run switch on the Admin page overrides everything.

Connect (LinkedIn, Naukri, Instahyre, Cutshort, Wellfound): export that site's cookies from your own logged-in browser with a cookie-export extension (the usual cookies.json array) and upload the file here. It is stored only in your private browser profile on this server, never in the repo; nothing types your password. Check opens the site headless with the saved profile and refreshes the Login column (ok / expired / challenge). A challenge means the site wants a captcha or OTP: finish it in your own browser, export again, re-connect.

Workday (account site): nothing to upload. Each company's career site wants its own candidate account, so a real apply run creates one with your profile email and a password it generates and keeps encrypted (never your mailbox password), confirms it with the code or link from your Mailbox, then walks the application wizard. A dry run never creates an account. external covers apply links on hosts that are not a known ATS: the form navigator finds the form (cookie banners, Apply buttons, popups, wizards) and may create an account there the same way, only when the global dry run is off and auto-submit is on for it.
